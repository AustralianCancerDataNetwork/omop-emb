    EmbeddingReaderInterface

    Backend-neutral read interface for embedding search and retrieval.

    Generic over the store type S it holds, so backend keeps the type of the store passed in.

    Parameters:

    Name Type Description Default
    backend S

    Store from open_vector_store_reader() or open_vector_store_writer().

    		 required
    metric_type MetricType

    Distance metric used for KNN queries and validated against the registry.

    		 required
    cdm_session_factory CDMSessionFactory

    Opens sessions on the user's OMOP CDM, e.g. from omop_alchemy.cross_database.cdm_sessionmaker. When provided, KNN results are enriched with concept_name from the CDM. When absent, concept_name is None. domain_id, vocabulary_id, is_standard, and is_active are populated directly from the embedding table by the backend.

    		 None
    model str

    Model name that is expected to be canonicalized by the constructor. A possibly-canonical name is accepted as we cannot know if canonical or not.

    		 required
    provider_type str

    omop-llm provider key. Defaults to 'ollama'.

    		 'ollama'
    k int

    Default number of nearest neighbors to return.

    		 DEFAULT_K_NEAREST
    faiss_cache_dir str

    Optional directory for FAISS index caching. If provided, the interface will attempt to use FAISS for faster KNN search. Only supported if the 'faiss' package is installed.

    		 None

    generate_embeddings staticmethod 

    generate_embeddings(
    model_backend: ModelBackend,
    text: Union[str, List[str], Tuple[str, ...]],
    *,
    role: EmbeddingRole,
    batch_size: Optional[int] = None,
) -> EmbeddingArray

    Embed text against model_backend, validating the resulting shape.

    Callable without an interface instance for callers that hold a ModelBackend directly (e.g. on-the-fly query embedding against a registry-resolved model, decoupled from any specific write session). Role-prefix application is model_backend's own job (see ModelBackend.embed_texts's role parameter); this method only forwards role and validates the returned shape.

    Parameters:

    Name Type Description Default
    model_backend ModelBackend

    Backend to generate embeddings with.

    		 required
    text str | list[str] | tuple[str, ...]

    Input text(s) to embed.

    		 required
    role EmbeddingRole

    Role of the input text(s), used by model_backend to apply a configured prefix.

    		 required
    batch_size int

    Forwarded to ModelBackend.embed_texts.

    		 None

    Returns:

    Type Description
    EmbeddingArray

    Float32 array of shape (n_texts, embedding_dim).

    Raises:

    Type Description
    RuntimeError

    If the model returns something other than a finite 2-D array, or a different number of vectors than texts.

    get_nearest_concepts(
    query_embedding: EmbeddingArray,
    *,
    concept_filter: Optional[EmbeddingConceptFilter] = None,
    k: Optional[int] = None,
    faiss_index_config: Optional[IndexConfig] = None,
) -> Tuple[Tuple[NearestConceptMatch, ...], ...]

    Return nearest stored concepts for each query embedding row.

    Parameters:

    Name Type Description Default
    query_embedding ndarray

    Shape (Q, D), Q query vectors of dimension D. D must match the embedding dimension for the registered model.

    		 required
    concept_filter EmbeddingConceptFilter

    In-DB pre-filter applied during KNN (domain, vocabulary, standard).

    		 None
    k int

    Number of nearest neighbors (defaults to interface-level k).

    		 None

    Returns:

    Type Description
    Tuple[Tuple[NearestConceptMatch, ...], ...]

    Shape (Q, ≤k). A row has fewer than k entries only when fewer than k stored concepts exist that match concept_filter (or exist at all). domain_id, vocabulary_id, is_standard, and is_active are always populated from the embedding table. concept_name is None if no CDM engine was provided to the interface.

    get_similar_concepts 

    get_similar_concepts(
    concept_ids: Union[int, Sequence[int]],
    k: Optional[int] = None,
    *,
    concept_filter: Optional[EmbeddingConceptFilter] = None,
    faiss_index_config: Optional[IndexConfig] = None,
) -> Tuple[Tuple[NearestConceptMatch, ...], ...]

    Return nearest stored concepts for one or more already-embedded concepts.

    Convenience wrapper around :meth:get_nearest_concepts: resolves each of concept_ids to its own stored embedding (via :meth:get_embeddings_by_concept_ids) instead of requiring the caller to fetch and pass a raw vector. Each concept is excluded from its own row of results.

    Parameters:

    Name Type Description Default
    concept_ids int or sequence of int

    One or more concept IDs to search neighbours for. Every ID must already have a stored embedding. A bare int is treated as a single-element sequence.

    		 required
    k int

    Number of nearest neighbours to return per query concept (defaults to interface-level k).

    		 None
    concept_filter EmbeddingConceptFilter

    In-DB pre-filter applied during KNN (domain, vocabulary, standard).

    		 None
    faiss_index_config IndexConfig

    Required only if a FAISS cache is configured on this interface.

    		 None

    Returns:

    Type Description
    Tuple[Tuple[NearestConceptMatch, ...], ...]

    Shape (Q, ≤k) where Q == len(concept_ids) (1 for a bare int), in the same order as concept_ids. Each row excludes its own query concept.

    Raises:

    Type Description
    ValueError

    If concept_ids is empty, or any entry has no stored embedding.

    get_joint_embedding 

    get_joint_embedding(
    concept_ids: Tuple[int, ...],
    weights: Optional[Tuple[float, ...]] = None,
) -> np.ndarray

    Return the (optionally weighted) centroid of stored concept embeddings.

    Parameters:

    Name Type Description Default
    concept_ids tuple of int

    Concept IDs whose stored embeddings should be combined. Must be non-empty, and every ID must already have a stored embedding for the interface's model.

    		 required
    weights tuple of float

    Per-concept weight, same length as concept_ids. Defaults to an unweighted mean.

    		 None

    Returns:

    Type Description
    ndarray

    Shape (D,) centroid vector, suitable as a single query row for :meth:get_nearest_concepts. Not normalised: backends compute cosine distance directly from raw vectors (and the FAISS cache normalises query vectors internally for COSINE), so this method has no normalisation to do regardless of metric_type.

    Raises:

    Type Description
    ValueError

    If concept_ids is empty, weights has a mismatched length, weights sums to zero, or any concept_ids entry has no stored embedding.

    BackendType

    Bases: StrEnum

    Embedding storage backend.

    Members

    SQLITEVEC Default backend. Requires no external database server. PGVECTOR Optional backend. Requires a PostgreSQL instance with the pgvector extension (pip install omop-emb[pgvector]). DUCKDBVSS Optional backend. Requires a DuckDB database and its VSS extension (pip install omop-emb[duckdbvss]).

    IndexType

    Bases: StrEnum

    Index structure built on an embedding table for nearest-neighbor search.

    Members

    FLAT Exact sequential scan. Always correct, slower at scale. HNSW Approximate nearest-neighbor index. Supported by pgvector, DuckDB VSS, and FAISS, not by sqlite-vec.

    MetricType

    Bases: StrEnum

    Distance metric used for nearest-neighbor search.

    Members

    L2 Euclidean (L2) distance. COSINE Cosine distance. L1 Manhattan (L1) distance. HAMMING Hamming distance (bit vectors). JACCARD Jaccard distance (bit vectors).

    FlatIndexConfig dataclass

    Bases: IndexConfig

    Configuration for a flat (exact scan) embedding table.

    Attributes:

    Name Type Description
    index_type IndexType

    Always IndexType.FLAT.
    metric_type MetricType or None

    Backends that fix the metric on the table (sqlite-vec) lock the model to it and default to cosine. Backends that compute distances from the raw vectors (pgvector) drop it, so queries choose the metric.

    HNSWIndexConfig dataclass

    Bases: IndexConfig

    Configuration for an HNSW approximate nearest-neighbour index.

    Attributes:

    Name Type Description
    index_type IndexType

    Always IndexType.HNSW.
    metric_type MetricType

    Distance metric locked to this index. Required; cannot be None.
    num_neighbors int

    Number of bi-directional links per node (M in the HNSW paper). Default 32.
    ef_search int

    Size of the dynamic candidate list during search. Default 16.
    ef_construction int

    Size of the dynamic candidate list during index construction. Default 64.
    Notes

    Supported by pgvector, DuckDB VSS, and FAISS backends. sqlite-vec does not support HNSW.

    EmbeddingModelRecord dataclass

    Immutable snapshot of one registered embedding model.

    Each record maps to exactly one row in the model_registry table, identified by model_name.

    Attributes:

    Name Type Description
    model_name str

    Canonical model name including tag (e.g. 'nomic-embed-text:v1.5').
    provider_type str

    omop-llm provider key that serves the model (e.g. 'ollama').
    index_config IndexConfig

    Active index configuration. index_type and metric_type are derived from this field via properties.
    dimensions int

    Embedding vector dimensionality.
    storage_identifier str

    Physical table name stored at registration. New names are store-scoped; existing rows keep the identifier already recorded here.
    metadata Mapping[str, object]

    Free-form operational data.
    created_at (datetime, optional)

    Row creation timestamp (UTC).
    updated_at (datetime, optional)

    Row last-updated timestamp (UTC).
    Notes

    metric_type is None for a FLAT model on a backend that computes distances from the raw vectors (pgvector). In that case any backend-supported metric is valid at query time. When metric_type is set (HNSW, or FLAT on a backend that fixes the metric on the table), queries must use that metric exactly.

    index_type property 

    index_type: IndexType

    Index type derived from index_config.

    metric_type property 

    metric_type: Optional[MetricType]

    Distance metric the model is locked to, or None if queries choose it.

    RegistryManager

    Registry of embedding models co-located with the embedding store.

    For sqlite-vec the engine points at the same .db file as the vec0 tables. For pgvector it points at the same Postgres database.

    Parameters:

    Name Type Description Default
    embedding_engine Engine

    SQLAlchemy embedding engine connected to the embedding store. Must have been built via registry_reader_engine()/registry_writer_engine(), which is checked here to ensure the registry schema claim is present.

    		 required
    Notes

    The registry table is created under the registry schema tag (a schema_translate_map key, resolved to the physical schema named by MODEL_REGISTRY_SCHEMA), independent of whichever schema the embedding store itself resolves to.

    Raises:

    Type Description
    UnregisteredSchemaTagError

    If embedding_engine wasn't built with the registry schema claim.

    registry_available property 

    registry_available: bool

    Whether the registry table currently exists on this engine.

    True for any writable-bootstrapped engine (ensure_registry_table already ran). May be False for a peek-constructed engine on a store that's never been configured -- callers must not assume this is always True.

    embedding_engine property 

    embedding_engine: Engine

    SQLAlchemy engine connected to the embedding store.

    emb_session_factory property 

    emb_session_factory: sessionmaker

    Session factory bound to embedding_engine.

    SQLiteVecEmbeddingBackend

    Bases: EmbeddingBackend[Table]

    sqlite-vec embedding backend.

    All data lives in a single .db file. vec0 virtual tables (embeddings) and the registry table share the same file and SQLAlchemy engine.

    Notes
    • Only the FLAT index type is supported. Each model is locked to one metric (L2, cosine or L1, cosine by default), declared on its vec0 table and recorded in the registry. rebuild_index recreates the table from the stored vectors when the metric differs or the table was created without a declared metric.
    • vec0 stores rows in fixed-size chunks and does not fill the free slots of an earlier chunk, so deleted or rewritten rows leave space that VACUUM alone does not return. compact_storage recreates the table to return it.
    • vec0 is a SQLite virtual table type the SQLAlchemy ORM cannot map, but it accepts ordinary SQL once created. _table_cache therefore stores a Core :class:~sqlalchemy.Table used for every query except the initial CREATE VIRTUAL TABLE.
